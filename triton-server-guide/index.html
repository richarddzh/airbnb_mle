      NVIDIA Triton Inference Server 中文入门与本地实验手册

      面向第一次接触推理服务器的开发者：从“它是什么”开始，在一张本地 NVIDIA GPU 上跑通模型，理解 request batching，并在 Windows + WSL2 中建立可重复的实验环境。

      最短答案：你可以用单张 NVIDIA GPU 学习 Triton；可以通过官方 vLLM backend 部署显存容纳的本地 LLM；也可以部署 TorchScript/PyTorch 模型。Windows 上首选 WSL2，而不是传统 Linux 虚拟机。

      你最关心的五个结论

      单 GPU：可以

      模型仓库、HTTP/gRPC、动态批处理、指标、trace 和单卡 LLM 都可以学习。多 GPU 并行和集群高可用不在单机实验范围内。

      先确认显存

      vLLM 部署 LLM：可以

      Triton 提供官方 vLLM backend 容器。Triton 管服务入口，vLLM AsyncEngine 管 paged attention 和 inflight/continuous batching。

      推荐生成式 LLM

      PyTorch：可以但需选对路径

      LibTorch backend 主要运行 TorchScript；普通 Hugging Face eager 模型通常用 Python backend，或直接选 vLLM/TensorRT-LLM。

      不要只复制 .pt

      观察 batching：可以

      用 perf_analyzer 逐级提高并发，用 Prometheus 的 inference/execution count 计算平均 batch size，再用 trace 查看排队和计算时间。

      做对照实验

      Windows：用 WSL2

      Docker Desktop 的 GPU 支持只在 WSL2 backend 上提供。WSL2 使用 Windows NVIDIA 驱动暴露 GPU，不需要传统虚拟机 PCIe passthrough。

      Windows 11 优先

      Triton 位于技术栈的哪一层

      Triton 不是训练框架，也不是模型格式；它是模型与客户端之间的推理服务、调度和可观测层。

      建议阅读顺序

      1. 先建立概念。阅读核心概念与架构，理解 model repository、backend、scheduler、model instance。
      2. 确认机器可行。阅读单 GPU 条件和Windows/WSL2，完成 GPU 容器验证。
      3. 跑通普通模型。按Quickstart 与模型仓库启动 Triton，先不要从 LLM 开始。
      4. 理解批处理。按Batching 实验建立无 batching/有 batching 的对照数据。
      5. 再部署 LLM。根据PyTorch与vLLM页面选择后端。

      最短实验路线

      PowerShell（管理员）：安装 WSL2 
      wsl --install -d Ubuntu
wsl --update
wsl -l -v
      WSL2：验证 Docker 能看到 GPU 
      nvidia-smi
docker run --rm --gpus all ubuntu nvidia-smi
      WSL2：启动 Triton（将版本与模型目录替换为实际值） 
      export TRITON_VERSION=<xx.yy>
docker run --gpus=1 --rm \
  -p 8000:8000 -p 8001:8001 -p 8002:8002 \
  -v "$PWD/model_repository:/models" \
  nvcr.io/nvidia/tritonserver:${TRITON_VERSION}-py3 \
  tritonserver --model-repository=/models
      另一终端：检查 server 与指标 
      curl -i localhost:8000/v2/health/ready
curl localhost:8002/metrics | head

      版本提示：<xx.yy> 是 Triton 的年月版本标签。请在 NGC Triton Server 标签页选择存在的版本，并让 server、SDK、backend 示例使用同一 release branch。不要盲目复制文档中的历史示例版本。
