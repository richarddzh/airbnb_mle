      Windows + WSL2 + RTX 4070 操作手册

      Triton 官方容器是 Linux 环境。Windows 用户最简单可靠的实验方式是 WSL2：Windows 安装 NVIDIA 驱动，WSL2 通过 GPU paravirtualization 使用同一张 RTX 4070，Docker 再把 GPU 暴露给 Triton 容器。

      推荐拓扑：Windows 11 → WSL2 Ubuntu → Docker Desktop WSL2 backend（或 WSL 内 Docker）→ Triton Linux container → RTX 4070 12GB。

      为什么不优先使用传统 Linux 虚拟机

      方案CUDA GPU入门难度建议
      WSL2NVIDIA GPU-PV，官方支持低首选
      Linux 双系统原生中；需分区和重启追求原生环境时考虑
      Hyper-V DDA / 企业 passthrough取决于硬件、宿主版本和设备支持高不适合普通入门
      VMware/VirtualBox 普通 3D 加速通常不是 CUDA passthrough看似低但达不到目标不要用于 Triton GPU 实验
      CPU Linux VM无中可学习 CPU server，但 WSL2 更轻

      GPU 数据路径

      flowchart LR W["Windows 11
      NVIDIA display driver"] --> P["WSL2 GPU-PV
      Linux CUDA interface"] P --> D["Docker Desktop
      WSL2 backend"] D --> C["Triton Linux container
      --gpus=1"] C --> G["RTX 4070
      12GB VRAM"]

      不要在 WSL2 里安装 Linux NVIDIA display driver：NVIDIA CUDA on WSL 指南说明，Windows 主机驱动会以映射方式提供 CUDA 支持。若要安装 CUDA toolkit，只选择 WSL-Ubuntu toolkit，不要安装会覆盖驱动的 meta-package。

      步骤 1：更新 Windows 与 NVIDIA 驱动

      1. 优先使用 Windows 11，并完成 Windows Update。
      2. 从 NVIDIA 官方安装支持 WSL2 CUDA 的最新稳定驱动。
      3. 重启 Windows。
      4. 在 PowerShell 运行：
      nvidia-smi

      确认型号为 RTX 4070、显存约 12GB，记录 Driver Version。若这一步失败，WSL2 和 Docker 都不会成功。

      步骤 2：安装 WSL2 Ubuntu

      管理员 PowerShell 
      wsl --install -d Ubuntu
wsl --update
wsl --set-default-version 2

      重启后首次打开 Ubuntu，创建 Linux 用户名和密码。然后回到 PowerShell：

      wsl -l -v
wsl --status

      Ubuntu 的 VERSION 应为 2。若已有 WSL1：

      wsl --set-version Ubuntu 2

      步骤 3：在 WSL2 验证 GPU

      Ubuntu / WSL2 
      nvidia-smi
ls -l /usr/lib/wsl/lib/libcuda.so*
uname -a

      nvidia-smi 应看到 RTX 4070。WSL 里的显示可能与 Windows 版本略有差异，但设备必须可见。

      步骤 4：安装 Docker

      方案 A：Docker Desktop（推荐新手）

      1. 安装最新 Docker Desktop for Windows。
      2. Settings → General：启用 “Use the WSL 2 based engine”。
      3. Settings → Resources → WSL Integration：启用 Ubuntu。
      4. 重启 Docker Desktop。

      Docker 官方明确说明：Docker Desktop for Windows 的 GPU 支持只在 WSL2 backend 可用。

      方案 B：直接在 WSL2 安装 Docker Engine

      适合熟悉 Linux 服务管理的用户。按 Docker Engine Ubuntu 官方步骤安装，并按 NVIDIA Container Toolkit 指南配置 runtime。两套 Docker 不要混用，以免 socket/context 混乱。

      步骤 5：验证容器 GPU

      Ubuntu / WSL2 
      docker version
docker info
docker run --rm --gpus all ubuntu nvidia-smi

      如果权限不足，Docker Desktop 路径通常不要求 Linux docker group；原生 Docker Engine 可按官方说明配置用户权限。不要用长期 sudo chmod 666 /var/run/docker.sock 作为修复。

      步骤 6：创建 Linux 文件系统实验目录

      mkdir -p ~/triton-lab/model_repository
cd ~/triton-lab

      推荐通过 Windows Explorer 的 \\wsl$\Ubuntu\home\<user>\triton-lab 查看文件，或使用 VS Code Remote WSL。模型和大量小文件放 Linux home，避免 /mnt/c 的性能和权限差异。

      步骤 7：启动 Triton

      RTX 4070 GPU 路径

      export TRITON_VERSION=<xx.yy>
docker pull nvcr.io/nvidia/tritonserver:${TRITON_VERSION}-py3

docker run --gpus=1 --rm \
  --shm-size=1g \
  -p 8000:8000 -p 8001:8001 -p 8002:8002 \
  -v "$PWD/model_repository:/models" \
  nvcr.io/nvidia/tritonserver:${TRITON_VERSION}-py3 \
  tritonserver --model-repository=/models

      CPU-only 路径

      export TRITON_VERSION=<xx.yy>
docker run --rm \
  --shm-size=1g \
  -p 8000:8000 -p 8001:8001 -p 8002:8002 \
  -v "$PWD/model_repository:/models" \
  nvcr.io/nvidia/tritonserver:${TRITON_VERSION}-py3 \
  tritonserver --model-repository=/models

      CPU 路径不要带 --gpus，且模型配置必须能运行在 CPU。使用本手册 add/sub Python backend 示例最稳妥。

      从 Windows 访问 WSL2 中的 Triton

      Docker Desktop 映射的端口通常可直接从 Windows localhost 访问：

      Windows PowerShell 
      curl.exe -i http://localhost:8000/v2/health/ready
curl.exe http://localhost:8002/metrics

      PowerShell 的 curl 在旧版本中可能是别名，因此示例显式使用 curl.exe。

      RTX 4070 12GB 专用建议

      • Windows 桌面也会占用一部分显存；不要把 12GB 全部承诺给 engine。
      • vLLM 从 gpu_memory_utilization=0.80 或 0.85 起步。
      • 选择 0.5B–3B 模型作为第一条成功路径；7B FP16 通常没有足够安全余量。
      • 先把 max_model_len 限为 2048，稳定后再提高。
      • 单模型、单 instance、并发 1 起步；每次只改变一个变量。
      • 用 watch -n 1 nvidia-smi 观察显存；Windows 侧也可用任务管理器 GPU 页面辅助观察。

      CPU 机器能学到什么

      可做不建议当作目标
      Python backend add/sub、模型仓库、版本、health、HTTP/gRPC高性能 LLM token generation
      用小模型观察 queue、dynamic batching 和 execution count推断 GPU 上的真实吞吐和 kernel 行为
      学习 metrics、trace、模型加载错误排查验证 GPU memory、paged attention 和 CUDA graph
