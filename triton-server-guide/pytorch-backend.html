      用 PyTorch 作为 Triton 后端

      “PyTorch 模型”不只有一种接入方式。官方 PyTorch/LibTorch backend 主要直接运行 TorchScript；Python backend 可以运行普通 Python/PyTorch；生成式 LLM 通常更适合 vLLM 或 TensorRT-LLM。

      先做正确选型

      路径模型形式适合主要限制
      PyTorch (LibTorch) backendTorchScript model.pt；新版本另有 AOT Inductor PT2 支持结构稳定的 PyTorch tensor 模型普通 eager Python 模型需先转换；版本与算子兼容重要
      Python backendmodel.py 中加载 PyTorch/Transformers原型、自定义前后处理、难转换模型Python 进程、依赖环境、性能和内存需自己管理
      vLLM backendvLLM 支持的生成式 LLMtoken generation、continuous batching、paged attention受 vLLM 模型/量化支持约束
      TensorRT-LLM backend构建后的 TensorRT-LLM engineNVIDIA GPU 上追求生产性能构建和版本组合更复杂

      常见误解：不能把 Hugging Face 下载的任意 pytorch_model.bin 或 model.safetensors 直接改名为 model.pt 放进 PyTorch backend。LibTorch backend 期待的是可加载的 TorchScript（或对应版本支持的编译包）。

      路径 A：TorchScript 小模型

      以下流程适合 RTX 4070，也可把模型配置为 CPU instance 在 CPU 机器上学习。

      1. 导出 TorchScript

      export_model.py（在合适的 PyTorch 环境运行） 
      import torch


class TinyModel(torch.nn.Module):
    def forward(self, input0, input1):
        return input0 + input1


model = TinyModel().eval()
example = (torch.randn(1, 4), torch.randn(1, 4))
scripted = torch.jit.trace(model, example)
scripted.save("model.pt")

      生产模型应验证 trace 是否覆盖控制流；依赖数据控制流的模型可能需要 torch.jit.script，而不是 trace。

      2. 建立仓库

      model_repository/
└── tiny_torch/
    ├── config.pbtxt
    └── 1/
        └── model.pt
      tiny_torch/config.pbtxt 
      name: "tiny_torch"
platform: "pytorch_libtorch"
max_batch_size: 8

input [
  { name: "input0" data_type: TYPE_FP32 dims: [4] },
  { name: "input1" data_type: TYPE_FP32 dims: [4] }
]
output [
  { name: "OUTPUT__0" data_type: TYPE_FP32 dims: [4] }
]

dynamic_batching {}

instance_group [
  { count: 1 kind: KIND_GPU }
]

      PyTorch backend 因 TorchScript metadata 限制有输入/输出命名约定。输入可匹配 forward 参数名，或统一使用 INPUT__0 位置命名；输出常用 OUTPUT__0。以当前官方 backend 文档为准。

      3. CPU-only 配置

      将 instance 改成 CPU，或根据 backend 默认行为省略显式 instance group：

      instance_group [
  { count: 1 kind: KIND_CPU }
]

      容器兼容：官方 PyTorch backend 使用与 Triton release 匹配的 LibTorch。你在任意本地 PyTorch 版本导出的模型不一定无条件兼容。若加载失败，先核对对应 Triton/PyTorch release notes 和算子支持。

      路径 B：Python backend 包装 PyTorch

      如果模型无法方便转 TorchScript，可以在 model.py 中加载 eager-mode PyTorch。基本生命周期如下：

      flowchart LR A["auto_complete_config()
      可选"] --> I["initialize()
      加载 tokenizer / model"] I --> E["execute(requests)
      必须"] E --> R["InferenceResponse"] E --> E E --> F["finalize()
      可选清理"]
      • initialize 每个 model instance 调一次，模型应在这里加载，而不是每个请求重复加载。
      • execute 收到请求列表；必须为每个请求返回响应，除非模型使用 decoupled transaction policy。
      • 第三方 Python 依赖要放入容器，或使用 Python execution environment。
      • 多个 Python model instance 可能各自复制模型，RTX 4070 12GB 上很容易重复占显存。

      能否用 PyTorch backend 部署 local LLM

      可以，但“能”不等于“推荐”。

      • 若 LLM 能稳定导出为受支持 TorchScript/PT2，并且你自己实现 tokenization、autoregressive loop、KV cache 和 streaming，理论上可用。
      • 若通过 Python backend 直接调用 Transformers，可以更快跑通，但 batching、KV cache、流式响应、取消请求和显存管理都需谨慎处理。
      • 对真正的文本生成服务，vLLM 已提供 continuous batching 和 paged attention，通常更适合 RTX 4070 的 12GB 显存。

      RTX 4070 12GB 的选择建议

      目标建议
      学习 Triton tensor batching小型 TorchScript/ONNX 模型，batch 1–16，单 GPU instance
      加载普通 PyTorch 模型先做 TorchScript 小例子；复杂模型再评估 Python backend
      本地聊天 LLM优先 vLLM backend，选小模型/适配量化，限制上下文与并发
      CPU 机器学习 serverPython backend add/sub 或小型 ONNX/TorchScript CPU 模型；不以 LLM 性能为目标

      故障定位

      • cannot load model：检查文件是否真的是 TorchScript、文件名、platform 和 release 兼容。
      • unknown input/output：检查 TorchScript forward 参数与 INPUT__n/OUTPUT__n 命名约定。
      • shape mismatch：若 max_batch_size > 0，配置 dims 不包含首个 batch 维。
      • CUDA OOM：先将 instance count 设 1，缩小模型/batch，并确认没有其他进程占显存。
      • Python import error：依赖不在 Python backend stub 环境内，需构建镜像或配置 execution environment。
