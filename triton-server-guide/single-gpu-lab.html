      只有一张 GPU，能否学习 Triton？

      能。NVIDIA Quickstart 的 GPU 示例本身就使用 --gpus=1。单卡足够覆盖 Triton 最重要的学习目标，真正限制通常来自模型显存，而不是 Triton 要求多卡。

      推荐策略：先用小型 ONNX/TorchScript 模型学习 Triton 的仓库、协议和 dynamic batching；再用显存可容纳的小型 LLM 学习 vLLM backend。这样能把“服务器机制问题”和“LLM 显存问题”分开。

      硬件与软件最低条件

      • GPU：支持 CUDA 的 NVIDIA GPU；具体 compute capability 和驱动要求取决于所选 Triton 容器版本。
      • 驱动：宿主机 NVIDIA 驱动必须满足容器所需 CUDA 的最低 driver 版本。容器带 CUDA 用户态库，但不会替你提供宿主驱动。
      • 系统：原生 Linux 最直接；Windows 建议 WSL2。
      • 容器：Docker 能以 --gpus all 或 --gpus=1 访问 GPU。
      • 内存与磁盘：除 GPU 显存外，容器镜像、模型权重和 Hugging Face cache 会占用大量磁盘和系统内存。

      显存如何估算

      只计算权重是不够的。LLM 推理显存可粗略拆成：

      flowchart LR W["模型权重
      参数量 × 每参数字节"] --> T["总显存需求"] K["KV cache
      上下文 × 并发 × 层数"] --> T R["Runtime workspace
      CUDA graph / kernels"] --> T A["激活、临时 tensor
      tokenization buffers"] --> T O["安全余量
      碎片与其他进程"] --> T
      权重精度理论每参数仅权重示例：7B说明
      FP324 bytes约 28 GB本地推理通常不划算
      FP16/BF162 bytes约 14 GB还未计 KV cache 与 runtime
      INT8约 1 byte约 7 GB实际取决于量化格式和 engine 支持
      INT4约 0.5 byte约 3.5 GB仍有 scales、metadata 和运行时开销

      不要把表格当成保证：即使权重“看起来放得下”，长上下文和高并发的 KV cache 也可能触发 OOM。入门时先用 0.5B–3B 量级或更小模型，并限制最大上下文和并发。

      四步检查机器

      1. 宿主机识别 GPU。
        nvidia-smi
        记录 GPU 型号、显存总量和 driver 版本。
      2. Linux/WSL2 识别 GPU。
        nvidia-smi
uname -a
        Windows 详见 WSL2 页面。
      3. 容器识别 GPU。
        docker run --rm --gpus all ubuntu nvidia-smi
        若这里失败，先不要启动 Triton。
      4. Triton 容器识别 GPU。
        docker run --rm --gpus=1 \
  nvcr.io/nvidia/tritonserver:<xx.yy>-py3 nvidia-smi

      单卡资源隔离建议

      • 实验时关闭占显存的软件和其他模型进程，先用 nvidia-smi 查看空闲显存。
      • 一次只加载一个 LLM；模型仓库可保留多个目录，但用 explicit model control 或单独仓库控制加载。
      • 不要一开始设置多个 model instance。每个实例通常会增加模型与 runtime 资源占用。
      • 对普通小模型，从 instance_group [{ count: 1 kind: KIND_GPU }] 开始。
      • 对 vLLM，限制 max model length、并发和 GPU memory utilization，具体参数以匹配的 vLLM release 为准。

      CPU-only 是否能学习

      Triton 可以不带 --gpus 启动。你仍可学习模型仓库、health、HTTP/gRPC 和 CPU backend；但要求 GPU 的模型配置无法加载，vLLM GPU 路径和 GPU batching 性能也无法真实实验。

      docker run --rm \
  -p 8000:8000 -p 8001:8001 -p 8002:8002 \
  -v "$PWD/model_repository:/models" \
  nvcr.io/nvidia/tritonserver:<xx.yy>-py3 \
  tritonserver --model-repository=/models

      成功标准

      • 容器内 nvidia-smi 能看到同一张 GPU。
      • Triton 启动日志列出模型并显示 READY。
      • /v2/health/ready 返回 HTTP 200。
      • :8002/metrics 出现 Triton 和 GPU 指标。
      • 并发提高时能看到吞吐、队列和 execution count 的变化。
