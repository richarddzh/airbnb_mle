USHER：面向资源优化 ML 推理的整体干扰规避

论文：Sudipta Saha Shubha 等，Usher: Holistic Interference Avoidance for Resource-Optimized ML Inference，OSDI 2024。
核心思想：GPU 共置不能只看显存是否放得下；必须联合约束计算、显存带宽/容量和 cache interference，并主动寻找资源互补的模型组合。

1. 为什么 batching 和 GPU 利用率不够

batch size 同时影响计算与显存，但只有一个旋钮，不能保证两类资源同时饱和。空间复用虽能把多个模型放到一张 GPU，却会引入 SM、显存和 cache 竞争。论文观察到，已有系统即使把计算/显存利用率推高，二者差值仍可达 5.3%–44.9%；GPUlet 中 87% 的模型、AlpaServe 中 100% 的模型，共置后的 goodput 不超过独占时的 55%。

关键结论：“GPU 看起来很忙”并不等于“有效完成了更多满足 SLO 的请求”。调度器必须优化 goodput，而不是裸 utilization。

2. 三个核心组件

组件职责解决的错误假设
GK-Estimator估计模型在特定 batch size 与 GPU 类型下的计算需求 \(C_{req}\)、显存需求 \(M_{req}\) 和执行时间。不能用模型大小或 FLOPs 单独代表运行时压力。
IR-Scheduler联合选择 batch、replica、GPU 类型与 placement，使 C-heavy 和 M-heavy workload 互补。“显存装得下即可共置”会造成严重干扰。
OG-Merger融合架构与权重相似模型的 operator graph，提高 cache 内容复用。空间切分无法隔离共享 cache 的争用。

3. GK-Estimator 如何得到调度输入

模型的 ONNX operator graph 被转换为 kernel graph。开始时间差不超过 \(\tau=0.001\)ms 的 kernel 被视为可能并发。系统用两个 stacked regressors 分别预测计算与显存需求，基学习器包括 Lasso、Kernel Ridge、Gradient Boosting 和 XGBoost。

特征包括 batch size、kernel 参数张量大小、输入/中间张量大小、FLOPs 和 GPU 类型。论文 20 个模型上，计算与显存需求估计准确率均为 99.98%；单次估计约 31.6ms，而逐模型真实 profiling 需 4.8 小时并产生约 42.7 美元成本。

4. IR-Scheduler 的优化问题

固定集群

maximize   total_goodput
subject to replicas placed ≤ available GPUs
           per-GPU compute and memory constraints
           each model's latency SLO

弹性集群

minimize   total GPU cost
subject to total_goodput = total_workload
           per-GPU compute and memory constraints
           each model's latency SLO

单模型 goodput 近似为 batch_size / (batch_execution_time + queueing_time)。搜索空间包含 batch size {4,8,16,32,64,128}、replication degree、GPU 类型和共置关系。

5. 具体放置流程

  1. 枚举可行 batch/replica 配置。先找到满足 SLO 的最小 replica 数 \(cl_M\)，再测试 \(RD=m\cdot cl_M,\ m\in\{1,\ldots,6\}\)。
  2. 计算资源向量。对每个候选配置得到 \(C_{req}\)、\(M_{req}\)、执行时间和 goodput。
  3. 标记资源类型。\(C/M\ge1.2\) 为 C-heavy，\(M/C\ge1.2\) 为 M-heavy，其余为 balanced。
  4. 互补分组。使用 k-means 变体最小化组内 \(\left|\sum C_{req}-\sum M_{req}\right|\)，让计算型与内存型模型互补。
  5. 降序放置。按 \(C_{req}+M_{req}\) 从大到小处理，并交替放置 C-heavy 与 M-heavy。
  6. best-fit 选 GPU。优先使用已承载同组模型的 GPU，并选择放置后剩余 C-space + M-space 最少的设备；若需新设备，选可承载且成本最低的 GPU 类型。
  7. 融合可共享 operator。对同 GPU 的相似模型执行 OG-Merger，进一步降低 cache interference。

6. OG-Merger 为什么重要

系统先用 DBSCAN 按 graph edit distance 聚类模型，再为模型对构造二部图。仅当 operator 类型相同、开始时间相同、权重相似度至少 40% 时连边；随后用 Hungarian algorithm 求最大权匹配，从权重矩阵提取最大公共子矩阵，为公共计算生成 GEMM，其余部分独立执行。

论文在随机模型上发现，52% 的 CNN 模型对权重相似度处于 45%–65%，70% 的 Transformer 模型对处于 55%–70%。去掉 OG-Merger 后 goodput 下降 55.7%，说明 cache 层干扰不是次要细节。

8. 对现代 LLM/Agentic AI 的迁移方式

USHER 的多资源 admission control 思想非常重要，但现代 LLM 需要扩展资源向量：

r = (
  SM / Tensor Core demand,
  HBM static weights,
  dynamic KV-cache and growth rate,
  memory bandwidth,
  L2/cache footprint,
  PCIe/NVLink/NVSwitch traffic,
  prefix/adapter locality,
  power and thermal headroom
)

prefill 通常更 compute-heavy，decode 更 memory/KV-heavy，因此不仅可以在“模型之间”做资源互补，也可以在“阶段之间”做互补组批。但必须用真实共置 profile 校准，因为 MPS 配额无法隔离 memory bandwidth、L2 cache 与互联竞争。

9. 局限

  • 论文主要覆盖传统 CNN/Transformer，最大 LLM 为 Llama-2 13B，未直接建模长上下文动态 KV-cache。
  • 仅实现 FP16，未覆盖 FP8/FP32 与量化精度对干扰的影响。
  • parallelism 由底层框架决定，未联合搜索 TP/PP/EP 与 placement。
  • 6,000 GPU 为模拟结果；公开代码明确是 preliminary artifact。
