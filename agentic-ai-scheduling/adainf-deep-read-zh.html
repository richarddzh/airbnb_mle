AdaInf：数据漂移下准确率与 SLO 联合调度

论文：Sudipta Saha Shubha 等，AdaInf: Data-Drift Adaptive Scheduling for Accurate and SLO-guaranteed Multiple-Model Inference Serving at Edge Servers，SIGCOMM 2023。
核心思想：推理系统不能只优化延迟和吞吐；当数据分布变化时，还必须把“保持模型质量所需的重训练工作”纳入同一 GPU 预算。

1. 问题背景

边缘应用常由多个 DNN 组成 DAG，例如目标检测后再做人、车分类。压缩模型适合边缘部署，却更容易因光照、天气、视角和对象分布变化而掉准确率。持续重训练可以恢复质量，但与在线推理竞争有限 GPU；若先训练后推理，会违约，若永远推理优先，模型又持续过时。

论文观察显示，无重训练时准确率差距最高可达 27%；但已有方案每周期只有 53%–60% 的请求能用到最新模型。更重要的是，不同 DAG 节点受漂移影响差异很大，平均分配训练资源会浪费 GPU。

2. 系统假设与双时间尺度

  • 应用是多模型 DAG，推理和增量重训练共用边缘 GPU。
  • 每 50 秒形成一次新训练窗口，并重新评估漂移与训练需要。
  • 每 5ms 把新请求组成 job；默认 job SLO 为 400–600ms。
  • GPU 通过 NVIDIA MPS 空间切分。
  • 云端 golden model 为新样本提供标签。
AdaInf 最值得复用的不是具体 50s/5ms 参数，而是“慢速质量控制 + 快速执行控制”的分层结构。

3. 数据漂移如何量化

  1. 压缩特征。对新训练样本的特征执行 PCA。
  2. 估计新颖度。计算新样本与旧样本平均特征的 cosine distance。
  3. 抽取代表性样本。选择距离最大的 \(S\) 个样本。
  4. 测量质量。用当前完整模型推理，得到新数据准确率 \(I'_m\)。
  5. 判定与定量。若 \(I'_m<I_m\)，需要重训练；漂移影响度 \(d_m=I_m-I'_m\)。
  6. 自适应采样。\(S\) 从全部样本的 3% 开始，每次增加 3%；连续 4 次判断不变后停止。实验中 18% 即与全量判断一致。

4. 分层调度算法

4.1 应用间 GPU 空间

系统离线 profile 各应用在不同 batch size 和完整 GPU 下的 per-batch latency，选取最低 worst-case latency \(L_i^w\)，再用非线性回归估计满足 SLO \(L_i^s\) 所需的 GPU 空间 \(G_i\)。相对份额为：

G_i^a = G_i / Σ G_i

分配空间后，再结合 early-exit 结构重新选 batch size，避免把 full-GPU 最优 batch 机械搬到切分后的 GPU。

4.2 推理与重训练时间

在线推理先获得满足 SLO 所需的执行时间，剩余预算用于训练：

T_i^r = L_i^s - Σ(k∈I_i) l_ik

应用内部按漂移影响度分配训练时间：

T_ij^r = T_i^r × d_ij / Σ_j d_ij

随后从离线 profile 中选择在预算内预计准确率最高的样本数、training batch size 和 epoch 数。

4.3 Early exit 与 batch

每个模型预先生成多个 early-exit 结构。未漂移模型使用完整结构；需要训练的模型只考虑准确率不低于应用阈值 \(A_m\) 的结构，并选择推理延迟最低者。论文显示 GPU 份额和 early-exit 结构变化都会改变最优 batch，因此三者不能彼此独立配置。

4.4 CPU–GPU 内容管理

同一 layer 会先完成一个 batch 的全部请求再允许参数换出，以最大化当前内容复用。job 完成时丢弃 intermediate outputs，但保留更新参数。换出优先级为：

S_c = (1 - α) R_c + α L_i^s,   α = 0.4

\(R_c\) 表示预计再次使用时间；高分内容优先换出，预计很快复用的内容若被换出则保留在 CPU pinned memory。

5. 完整在线流程

  1. 慢速控制器收集新数据并计算每个 DAG 节点的漂移影响度。
  2. 重建本周期的 inference–retraining DAG，过滤不需要训练的节点。
  3. 基于 SLO 与性能模型，为应用分配 MPS GPU 空间。
  4. 为每个模型选择 early-exit 和 batch size。
  5. 每 5ms 快速控制器收集 job，并在约 2ms 内排定未来时间片。
  6. 先保证关键路径推理，再把剩余时间按漂移影响度分给增量重训练。
  7. 根据 DAG 依赖和内容复用时间决定执行顺序、参数驻留与 eviction。
  8. 周期末更新质量收益和性能回归，进入下一轮。

7. 对 Agentic AI 的启示

Agentic 服务也存在“质量维护工作”：检索索引更新、reranker/calibrator 刷新、安全策略模型更新、adapter 热加载、工具结果缓存更新等。它们类似 AdaInf 的增量重训练，应与在线 LLM 调用共享资源预算，而不是作为不可见后台任务。

AdaInf 概念Agentic AI 对应项
模型 DAGplanner → retrieval/tool → reasoning → synthesis → safety/rerank。
data drift impact工具分布、用户意图、检索语料或安全分布变化导致的质量风险。
early exit缩短 reasoning budget、减少候选、使用小模型/低精度或跳过非关键步骤。
训练时间预算索引构建、adapter 更新、cache warming 等后台维护预算。
应用准确率端到端任务成功率、groundedness、tool success 与 policy compliance。

8. 局限

  • 仅支持单边缘服务器和同类型 GPU。
  • 更换模型后需要重新 profiling；early-exit 点生成不在范围内。
  • 依赖云端 golden model 标签，带来成本、网络与隐私前提。
  • batch、空间和 early-exit 仍是分阶段启发式选择，而非联合全局最优。
