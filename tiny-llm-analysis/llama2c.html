    llama2.c：用 700 行纯 C 推理 Llama 2

    项目：github.com/karpathy/llama2.c　 作者：Andrej Karpathy。目标：用 PyTorch 训练 Llama 2 架构，再用一个约 700 行、零依赖的 C 文件（run.c）完成推理。 它脱胎自 nanoGPT，把架构从 GPT-2 换成 Llama 2，核心是那份纯 C 推理引擎。

    设计哲学：与 llama.cpp 相比，Karpathy 想要的是极简、最小、可教学—— 因此硬编码 Llama 2 架构，只用一份纯 C、无依赖的推理文件。目标是成为"训练/微调并部署微型 LLM（约 100M~1B 参数） 到边缘设备（MCU、手机、浏览器、笔记本）"这一工作流最简单、最可魔改的仓库。

    1. 项目全景与代码构成

    项目是一个"全栈"训练 + 推理方案，Python 侧负责训练与导出，C 侧负责推理。

    文件作用

    export.py把 PyTorch 检查点导出为 run.c 可读的 .bin（version 0/1/2，含量化）

    runq.cint8 量化版推理引擎（Q8_0）

    tokenizer.py / tokenizer.bin分词器训练与导出为 C 可读格式
    test.c / test_all.py把 C 与 Python 前向 200 步对齐校验

    2. 模型架构（model.py）

    model.py 实现的是标准 Llama 2 架构。相比 GPT-1/GPT-2，主要区别有： ① 用 RoPE 旋转位置编码取代绝对/学习式位置编码；② 前馈用更花哨的 SwiGLU； ③ 用 RMSNorm 取代 LayerNorm；④ 所有 Linear 层 bias=False；⑤ 可选多查询注意力（multiquery/GQA）。

    2.1 超参 ModelArgs

    字段含义Llama-7B 默认
    dim模型隐藏维4096
    n_layersTransformer 层数32
    n_heads查询头数32
    n_kv_headsKV 头数（可小于查询头 → 多查询）None(=n_heads)
    vocab_size词表大小32000
    hidden_dimFFN 隐藏维≈ 4·dim·2/3 对齐到 multiple_of
    multiple_ofFFN 隐藏维对齐倍数256
    norm_epsRMSNorm eps1e-5
    max_seq_len最大上下文2048

    2.2 核心组件逐块拆解

    • RMSNorm：x · rsqrt(mean(x²)+eps) · weight，先在 fp32 上算再转回原精度。
    • RoPE：precompute_freqs_cis 预计算 cos/sin，apply_rotary_emb 把 Q/K 视作复数对旋转（相对位置编码）。
    • Attention（GQA）：wq/wk/wv/wo 四个无偏置线性层。KV 头可少于 Q 头，用 repeat_kv 把 KV 复制 n_rep 份共享——这就是分组多查询注意力，省 KV 缓存。若 PyTorch≥2.0 用 flash attention，否则手写带因果 mask 的 softmax。
    • FeedForward（SwiGLU）：w2(silu(w1(x)) · w3(x))，三个线性层。
    • TransformerBlock：h = x + attn(attention_norm(x)) → out = h + ffn(ffn_norm(h))（前置归一化 + 残差）。
    • 权重绑定：tok_embeddings.weight = output.weight，输入嵌入与输出分类头共享权重。
    • 残差投影特殊初始化：对 w3/wo 用 std = 0.02/√(2·n_layers)（GPT-2 论文做法）。

    2.3 训练侧 vs 推理侧的一个小优化

    前向时，如果给了 targets（训练），就对所有位置算 logits 并求交叉熵； 如果没给（推理），只对最后一个位置算 logits——省掉无用计算。此外 estimate_mfu 会按 flops_per_token = 6N + 12·L·H·Q·T 估算 A100 bf16 的算力利用率（MFU）。

    3. 如何训练一个 baby Llama

    3.1 数据准备（tinystories.py）

    下载 TinyStories，用 SentencePiece 训练自定义 BPE（默认可选 4096 等小词表），预分词后存为 token 流供训练读取。 小词表的好处：嵌入表更小 → 参数更少、推理更快、序列更短。

    3.2 训练配方（train.py）

    README 给出的 110M 模型真实训练配方（作者自评"并非最优但合理"）：

    元参数值
    dim / n_layers / n_heads768 / 12 / 12（每头 64 通道）
    seq_len1024
    batch_size16（A100 40GB 显存上限）
    gradient_accumulation_steps8
    每次更新总 token 数16 × 1024 × 8 = 131,072
    learning_rate4e-4（作者认为略低）
    max_iters200K（略高）
    dropout0.1
    并行DDP，4× A100，训练约 1 天

    调参经验（作者原话精炼）：参考 Chinchilla 论文末表理解 dim/n_layers/n_heads 如何协同缩放； 每次更新的总 batch token 数中等应用约 100K；先把 batch_size 拉满显存，再用梯度累积补到目标 token 数； 学习率能高就高，小网络甚至可用 1e-3+，中型 3e-4 较稳。

    4. 纯 C 推理实现（run.c）

    run.c 用三个结构体组织一切，无任何第三方依赖：

    结构体作用
    Config模型维度（dim / hidden_dim / n_layers / n_heads / n_kv_heads / vocab_size / seq_len）
    TransformerWeights所有权重指针（嵌入表、各层 RMSNorm、wq/wk/wv/wo、w1/w2/w3、最终 norm、可选分类头）
    RunState前向时的激活缓冲（x、xb、q/k/v、att、hb、logits、以及 KV 缓存）

    4.1 权重加载：内存映射检查点

    C 侧用 mmap（Windows 走 win.c 兼容层）把 .bin 检查点直接映射进内存， 权重指针按固定顺序在文件上"就地绑定"，无需逐个 malloc+拷贝——这也是能在受限设备上运行的关键。

    4.2 前向单步 forward()

    flowchart TB E["memcpy 嵌入行 → x"] --> LP subgraph LP["逐层 l = 0..n_layers-1"] N1["rmsnorm(x) → xb"] --> QKV["matmul: wq/wk/wv
    k,v 直接写进 KV cache"] QKV --> ROPE["对 q,k 施加 RoPE 旋转"] ROPE --> MH["多头注意力 (#pragma omp 并行)
    score=q·k/√d → softmax → 加权 v"] MH --> WO["matmul(wo) → 残差回 x"] WO --> N2["rmsnorm(x) → xb"] N2 --> FFN["matmul w1,w3 → SwiGLU silu(w1)·w3 → matmul w2 → 残差"] end LP --> FN["rmsnorm 最终"] FN --> CLS["matmul(wcls) → logits"] CLS --> SMP["采样器: argmax / 温度+top-p"] SMP --> NEXT["下一个 token"] style MH fill:#eaf1fb,stroke:#2563c9 style FFN fill:#eaf6ec,stroke:#a3d9a5

    图 4-1　run.c 中 forward() 的单步计算流程

    • KV 缓存：key_cache/value_cache 按 [层][位置][kv_dim] 布局， 每步只算当前位置的 K/V 并写入缓存，注意力对 0..pos 历史求和。
    • RoPE：直接在循环里对 q、k 的每一对维度做复数旋转；rotn 控制只旋 q 还是 q+k（GQA 下 K 维更少）。
    • 多头注意力：用 #pragma omp parallel for 按头并行；每头点积→ /√head_size → softmax → 加权 value。
    • matmul：最朴素的 W(d,n)·x(n)，也用 OpenMP 并行行。
    • 采样器：支持贪心 argmax、温度缩放 + top-p（nucleus）采样。
    • 分词器：C 侧实现字节级 BPE 的合并/解码，从 tokenizer.bin 读词表与分数。

    性能：在 M1 MacBook Air 上，15M 模型 fp32 版约 110 tok/s。 用 -Ofast -fopenmp -march=native 及合适线程数（建议等于物理核数）可显著加速。

    5. int8 量化（runq.c）

    fp32 版每个权重占 4 字节，检查点大且慢。runq.c 采用 llama.cpp 术语的 Q8_0 量化： 对称量化到 [-127, 127]，只量化参与 matmul 的权重（RMSNorm 的缩放/偏置仍保 fp32，因为很敏感）。

    进一步地，它连激活也动态量化到 int8，使 matmul 变成纯整数运算——这才是提速的根本来源。

    指标（Llama-2 7B 为例）fp32int8 (Q8_0)
    检查点体积26 GB6.7 GB（↓4×）
    推理速度（OMP 64 线程）4.6 tok/s14 tok/s（↑3×）

    导出量化模型用 export.py --version 2；质量仅有轻微下降。README 也指出 LLM 甚至能容忍 4-bit ——这正是 esp32-ai 走 4-bit 路线的背景。

    6. 导出格式与自定义分词器

    • 导出版本：version 0（原始 fp32）、version 1（改进的 fp32 头部）、version 2（int8 量化）。 也可用 --meta-llama 导出 Meta 官方权重，或用 --hf 导出 HuggingFace 上的 Llama 2 架构模型。
    • 自定义分词器：默认 Llama 2 分词器 32000 词。小应用可训练更小词表（如 4096）， 用 -z data/tok4096.bin 传给 run.c。小词表 → 参数更少、更快、序列更短。

    7. 与本合集其它材料的联系

    • ← TinyStories：llama2.c 直接以 TinyStories 论文为"小模型可用"的依据，并用该数据集训练 baby Llama 系列。
    • → esp32-ai：esp32-ai 作者称 llama2.c 让很多人（包括他自己）相信"能训练一个微型 LM 并用纯 C 运行"。 但要强调：esp32-ai 在代码与方法上并不派生自 llama2.c（见其 RESULTS.md 的 Provenance 声明）， 二者是同一"微型 LM/单片机"空间里的独立工作。llama2.c 是 fp32/int8 的通用架构；esp32-ai 则专门为单片机内存层级做了 PLE + 4-bit 定制。

    8. 给初学者的一句话总结

    llama2.c 把"现代 LLM 到底怎么跑"这件事，剥到只剩一份能读懂的 C 文件：加载权重 → 逐层 RMSNorm/RoPE/注意力/SwiGLU → 采样下一个词。它是理解 Transformer 推理、KV 缓存、量化最好的"活教材"， 也是 esp32-ai 这类端侧项目的精神起点。
