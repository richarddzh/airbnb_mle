    微型 LLM 与端侧推理：分析报告合集

    本合集针对三份材料做详细、面向初学者的中文解读：一个把 2890 万参数模型塞进 8 美元单片机的开源项目、 奠定"微型语言模型也能说流利英语"这一论断的 TinyStories 论文、以及 Karpathy 用一个 C 文件跑 Llama 2 的经典项目 llama2.c。 并额外补充一份 Per-Layer Embeddings（PLE） 专题，解读 esp32-ai 所依赖的 Google Gemma 3n 内存技术。

    阅读建议：三份报告彼此独立又相互关联。如果你是完全的初学者，建议按 TinyStories 论文 → llama2.c → esp32-ai 的顺序阅读：先理解"为什么小模型能工作"， 再理解"如何用最简单的代码训练和推理一个小模型"，最后理解"如何把它压进单片机"。

    报告导航

    ① esp32-ai 项目解读

    在 8 美元的 ESP32-S3 单片机上运行 28.9M 参数 LLM。涵盖代码构成、训练流程、 Transformer 与 PLE 架构、纯 C 推理实现，以及三级存储的内存优化。

    代码 · 架构 · 内存优化

    ② TinyStories 论文解读

    arXiv:2305.07759。微软研究院提出用"三四岁小孩词汇量"的合成故事数据集， 让 1M~35M 参数的小模型也能生成连贯英文，并提出用 GPT-4 打分的评测范式。

    论文 · 数据集 · 评测

    ③ llama2.c 项目解读

    Andrej Karpathy 的极简项目：用 700 行纯 C（run.c）推理 Llama 2 架构， 配套 PyTorch 训练。涵盖模型定义、训练、导出格式与 int8 量化。

    纯 C 推理 · 训练 · 量化

    ④ Per-Layer Embeddings 解读

    esp32-ai 依赖的另一半核心：Google Gemma 3n 的逐层嵌入（PLE）。 含"它有没有论文"的诚实说明、原理、代码级实现，及它如何被 esp32-ai 复刻。

    Gemma 3n · 内存优化 · 溯源

    三者的关系

    这三份材料构成一条清晰的技术脉络：TinyStories 证明了"窄领域 + 小模型"的可行性； llama2.c 把这套思路做成最小可运行的训练/推理栈，并用 TinyStories 数据训练了一批 baby Llama； esp32-ai 则在此基础上，借助 Google Gemma 的 Per-Layer Embeddings（PLE）思想，把模型进一步压进单片机。
